## ١. كيف تشغّل البروتوتايب

**الأسهل:** انقر نقرتين على **`run-prototype.bat`** — يثبّت الاعتماديات، يشغّل الخادم، ويفتح Brave تلقائياً على <http://localhost:3000>

**أو يدوياً:**

```bash
cd app
npm install
npm run dev
```

شاشة الدخول تعطيك هويتين تجريبيتين: **طالب** و**مشرف**. جرّب الاثنتين — لوحة الإشراف تظهر للمشرف فقط.

> البيانات تُحفظ في `localStorage` بمتصفحك، فتبقى تعديلاتك بين الجلسات.
> لإعادة كل شيء للوضع الأصلي: افتح أدوات المطوّر ← Application ← Local Storage ← احذف `hadith-prototype-state-v1`.

**جرّب هذا:** ادخل كمشرف ← `/admin/settings` ← اخفض «الحد الأدنى المطلق للإخفاء» إلى ٢ ← ارجع للحديث الثالث. سترى تسجيلاً يُخفى تلقائياً أمامك. هذه ALG-002 تعمل حيّاً.

### روابط عرض مباشرة

أضف `?as=student` أو `?as=admin` لأي رابط لتفتحه فوراً بهوية تجريبية دون المرور بشاشة الدخول — مفيد للعرض والمشاركة:

```
http://localhost:3000/?as=student
http://localhost:3000/hadiths/h-001?as=student
http://localhost:3000/admin?as=admin
http://localhost:3000/admin/reports?as=admin
```

تُحذف هذه الآلية عند ربط Google OAuth الحقيقي (موضعها: `src/lib/store.tsx`).

## ٣. ما ينتظرك أنت (كل القيم تنكرية الآن)

كل شيء يحتاج تدخّلك موضوع في مكان واحد: **`app/.env.local.example`**

```
NEXT_PUBLIC_SUPABASE_URL=https://REPLACE-ME.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=REPLACE_ME_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY=REPLACE_ME_SERVICE_ROLE_KEY
NEXT_PUBLIC_ALLOWED_EMAIL_DOMAIN=          ← نطاق جامعتك
```

الشريط الأصفر أعلى التطبيق يذكّرك بأن المفاتيح ما تزال تنكرية، ويختفي وحده عند استبدالها.

طبقة البيانات كلها معزولة في `src/lib/store.tsx` و`src/lib/mock-data.ts` — استبدالها بـ Supabase لا يمسّ أي صفحة أو مكوّن.

## ٤. نتيجة نقد الـ SoT

الوثائق **جيدة بشكل غير معتاد**: ملفا SQL ينفَّذان بصفر أخطاء، و١٣/١٣ حالة استخدام مغطاة بأزواج كاملة، و٥٢ حالة اختبار كلها قابلة للتنفيذ.

لكن **٩ مشاكل P0** كانت ستُشحن بصمت. الثلاث الأخطر — كلها من نوع «لا يظهر خطأ، فقط لا تعمل الميزة»:

1. **لا مشغّل يصون `likes_count`** ⇒ العدّاد صفر للأبد ⇒ ALG-001 تختار عشوائياً.
2. **لا سياسة `UPDATE` على `recordings`** ⇒ المشرف لا يستطيع الاعتماد ✅ إطلاقاً ⇒ F008 معطّلة.
3. **`handle_new_user` ينتج اسماً < حرفين** ⇒ فشل تسجيل دخول كامل لمن بريده `x@…`.

**الوثائق حُدِّثت فعلياً إلى v1.1** — ٨ إصلاحات مطبَّقة داخل `04-database-schema.sql` و`05-rls-policies.sql` مباشرةً، وكلها أُعيد اختبارها من الصفر على PostgreSQL نظيف:

```
▸ DB-07  تسجيل دخول ببريد من حرف واحد → نجح، الاسم الاحتياطي «طالب-111111»
▸ DB-02  likes_count بعد إعجاب = 1 · بعد إلغائه = 0 · listens_count = 1
▸ DB-01  المشرف يعتمد → is_verified=true, verified_by مضبوط
▸ DB-01  طالب يحاول الاعتماد → ERROR: FORBIDDEN
▸ DB-03  زائر يقرأ profiles → 0 صف
▸ DB-04  زائر يقرأ app_settings → مفتاح واحد فقط (upload_enabled)
▸ DB-09  طالب يكتب في annotations → محجوب
▸ DB-06/08  استيراد معرّفات مستقرة ✓ · bitrate افتراضي 32 ✓
```

`hadith-sot/06-fixes.sql` بقي كـ**ترحيل (migration)** لمن نفّذ الإصدار 1.0 على Supabase بالفعل.

**التفاصيل:** `review/00-CRITIQUE-SUMMARY.md` — وفيه **٧ قرارات تنتظرك** (الخصوصية، حجم المكتبة، كسر التعادل، التراخيص، النسخ الاحتياطي…).
